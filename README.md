# 灵犀 · 聊天解读小工具

导入 QQ 聊天记录 → 用你自己配置的大模型读懂对方的情绪与潜台词，同时复盘「我」的回复哪里没说好、可以怎么改。

- **不猜玄学**：先用程序算出硬数据（谁更主动、谁回复更慢、谁在收尾、谁在连发轰炸），再让模型逐条读语气和潜台词。
- **只帮你说清楚**：每条「没接好」的话都会给出可以直接复制发送的改写，而不是空泛的「多关心她」。
- **模型随便换**：DeepSeek、OpenAI、任何 OpenAI 兼容中转站、通义千问 / GLM / Kimi、Claude、本地 Ollama / LM Studio 都支持。
- **数据不出本机**：网页服务只监听 `127.0.0.1`，接口配置（含 Key）存在你自己的 `config.json`，界面上只显示打码值，聊天内容只会发给你自己填的那个地址。

## 一、三步开始用

### 第 1 步：启动

双击 **`start.bat`**（Windows）。脚本会自动找到 Node 并打开浏览器。

> **请在文件资源管理器里双击，或者用 cmd 运行；不要在 PowerShell 里敲 `.\start.bat`。**
> 非要用 PowerShell 的话请写 `cmd /c start.bat`。
> `start.bat` 里一行中文都没有，这是故意的：cmd.exe 按系统代码页读 .bat 文件，里面写中文会被解析成乱码命令。

没有 Node.js 的话，去 <https://nodejs.org> 装 LTS 版本，装完再双击一次即可。**不需要 `npm install`**，本工具只用 Node 内置模块。

浏览器打开后是这个地址：`http://127.0.0.1:5178/`（端口被占会自动 +1）。

**更稳的启动方式**（跳过 .bat，一条命令，中文提示正常）：

```powershell
node tools\launch.js
```

这个包装器会先检查 Node 版本和文件是否齐全，打印中文横幅，出错时暂停窗口等你看清原因。`node server.js` 也依然可以直接用。

> 换端口：`node tools\launch.js --port 6000`；不自动开浏览器：加 `--no-open`；跑离线自检：`node tools\launch.js --selftest`

### 第 2 步：配好模型接口（可存多条，随时切换）

左侧「**3 模型接口**」是独立的一块，每条配置 = 一套「服务商 + 地址 + Key + 模型」：

1. 选服务商，地址和模型名会自动填好默认值；
2. 填上你的 API Key（可改配置名称，比如「DeepSeek 官方」「公司中转」）；
3. 点 **连接测试** —— 会真的发一次极小请求，成功后显示「连接正常 · 模型名 · 耗时」，失败会直接告诉你 401/404/429 的原因；
4. 点 **保存修改** 写入本机 `config.json`。

常用组合：

| 服务商 | Base URL | 模型 | 说明 |
| --- | --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 便宜、中文语感好，日常首选 |
| OpenAI 兼容中转 | 中转站给的地址（一般以 `/v1` 结尾） | 照抄中转站文档 | 国内直连最省事 |
| Anthropic Claude | `https://api.anthropic.com` | `claude-sonnet-4-5` | 潜台词把握通常最细 |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:14b` | 完全离线；先 `ollama pull qwen2.5:14b` |

配置管理：

- 顶部的下拉框切换当前使用的配置；右侧 **☰** 打开管理面板（每条都能单独测试/编辑/删除，还能「逐个测试全部配置」）；**⟳** 从 `config.json` 重新读取。
- **新建** 会加一条空配置，**删除** 会把这条（连同它的 Key）从 `config.json` 里移除。
- 想省事也可以直接复制 `config.example.json` 为 `config.json` 手写多条配置。
- Key 只写在本机 `config.json` 里，网页上显示的是打码后的 `••••••1234`；用打码值保存不会覆盖真实 Key。

### 第 3 步：导入记录并分析

把聊天记录粘贴进输入框（或直接拖 `.txt` 进去），填上「我是谁 / 对方是谁」，点 **开始分析**。

- 想先不花钱看一眼：点 **仅解析预览**，或者勾上 **只看本地统计，不调用模型**——这两种都不会调用模型。

## 二、怎么拿到 QQ 聊天记录

- **手机 QQ**：进入聊天 → 右上角「≡」→ 聊天记录 → 导出/生成 txt → 发给「文件传输助手」，在电脑上下载。
- **电脑 QQ**：打开聊天窗口，往上滚动加载想看的那段 → `Ctrl+A` 全选 → `Ctrl+C` 复制 → 粘贴进输入框。
- **导不出来时**：手动按 `昵称: 月-日 时:分:秒` 的格式敲几条关键的也能分析，10 条以上效果就比较稳了。

支持的格式（会自动识别）：

```
昵称: 10-08 19:01:50          ← 最常见
2024-10-08 19:01:50 昵称
[2024-10-08 19:01:50] 昵称
昵称 2024/10/8 19:01
```

其他细节：

- 只有「月-日」时会自动补当年，遇到 12 月接 1 月会自动判断跨年。
- 自动过滤「撤回了一条消息」「XXX 拍了拍 XXX」等系统提示。
- `[图片]`、`[动画表情]`、`[语音]` 会被标记为非文本消息，参与统计但不送去分析。
- HTML/XML 导出也能直接粘，会自动去标签。

## 三、报告怎么看

| 分区 | 内容 | 可信度 |
| --- | --- | --- |
| **本地统计** | 条数、平均字数、中位回复间隔、主动开启次数、收尾次数、连发、疑问句、0-6 点消息、聊天热度变化 | 硬数据，完全可信 |
| **总览** | 关系温度（0-100）、趋势、对方目前态度、关键信号 | 模型推测，看方向 |
| **逐条解读** | 每句关键话的情绪、字面、潜台词、把握度、可以怎么接 | 把握度 < 60% 的当参考 |
| **我的复盘** | 我哪句话没接好、问题在哪、**改写句** | 最实用的部分 |
| **下一步** | 该做/别做、新话题、下一条消息怎么发、要继续观察什么 | 可执行清单 |
| **试聊模拟** | 写下你准备发的话，预测对方最可能的 3 种反应 + 这条消息的风险 | 上线前先预演 |

报告可导出 **Markdown**（发到备忘录 / Notion / 微信收藏）和 **JSON**（自己再处理）。

## 四、工作原理（想改代码的话）

```
聊天记录文本
   │
   ├─ src/parser.js    → 识别格式、补年份、过滤系统消息、标记图片/语音/表情
   ├─ src/stats.js     → 本地硬统计（不花钱）+ 规则洞察
   │
   ├─ 记录 ≤ 400 条 ──→ 一次交给模型
   └─ 记录 > 400 条 ──→ 分段（每段 400 条，重叠 6 条）
                        → 每段独立分析成同一套 JSON
                        → 再让模型把各段结果汇总成整体判断
                          （汇总失败会本地合并兜底）
   │
   ├─ src/prompts.js   → 统一的输出协议（overview / insights / review / advice）
   ├─ src/analyzer.js  → 流程编排 + JSON 容错修复（截断、代码块、中文引号都能救）
   ├─ src/report.js    → Markdown 导出
   ├─ src/config-store.js → 接口配置读写与合并（Key 打码、旧格式兼容）
   └─ public/          → 网页界面（原生 JS，无框架）
```

关键设计：

- **接口配置是独立的一层**：多条配置存在 `config.json`，界面只拿到打码后的 Key；点「连接测试」会真的发一次极小请求（要求模型回 `{"ok":true,"echo":"pong"}`），把「地址 + Key + 模型名」一次验证完。
- **所有模型共用一套 JSON 协议**，所以换模型不用改任何代码；模型不听话时 `extractJson` 会自动修复（去代码块、补右括号、修引号、丢截断尾巴），仍然失败就自动重试一次，再失败就用其它分段的结果兜底。
- **硬数据先算好再给模型**，模型只负责解释，不负责数数，这样判断更稳、token 更省。
- **前端只和本机服务通信**，由服务端转发到模型接口，避免浏览器跨域问题，Key 也不会进 URL 或日志。

目录结构：

```
server.js               本地 HTTP 服务 + 模型 API 中转 + NDJSON 流式进度
start.bat               双击启动（纯 ASCII，避免 cmd.exe 乱码）
config.json             你的接口配置（首次「保存修改」后自动生成，含 Key，别外传）
config.example.json     配置模板
src/parser.js           聊天记录解析
src/stats.js            本地统计与规则洞察
src/prompts.js          提示词与输出协议
src/analyzer.js         分段分析、汇总、JSON 容错
src/report.js           Markdown 报告
src/llm.js              多厂商模型调用 + 连接测试
src/config-store.js     接口配置读写、合并、打码
public/                 网页界面（index.html / style.css / app.js）
tools/launch.js         启动包装器（找 Node、中文提示、出错暂停）
tools/selftest.js       离线自检（解析 / 统计 / 容错 / 报告 / 配置）
tools/fixtures.js       自检用的聊天记录样本
tools/check-encoding.js 编码检查（防止 .bat 乱码那类问题）
```

自检：`node tools/selftest.js`，不需要联网和 Key。

## 五、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 双击 start.bat 提示找不到 Node | 装 Node.js LTS；或把已有 Node 的路径写进环境变量 `NODE_EXE` |
| 运行 start.bat 出现乱码报错（如 `'呬綅缃?if' 不是内部或外部命令`） | 老版本 start.bat 里有中文导致的编码问题，已在 v1.0.1 修掉（.bat 现在是纯 ASCII）。若还有，直接用 `node tools\launch.js` |
| PowerShell 里 `.\start.bat` 报错 | 用 `cmd /c start.bat`，或直接在资源管理器双击；也可以直接 `node tools\launch.js` |
| 点「连接测试」报 `401` | API Key 没填 / 填错 |
| 点「连接测试」报 `404` | Base URL 或模型名不对。Base URL 一般以 `/v1` 结尾，模型名照抄服务商文档 |
| 连接测试报 `429` | 限流或额度用完 |
| 连接测试通过，但分析时报「不是合法 JSON」 | 换更强的模型；或把「每段消息条数」调小到 150-200；报告页「原文/日志」能看到模型原始输出 |
| 改了 config.json 但界面没变 | 点配置下拉框右边的 **⟳** 重新读取，或刷新页面 |
| 保存时报「config.json 不可写」 | 文件被占用或权限不足：关掉可能打开它的编辑器，或手动编辑该文件 |
| 解析出的说话人不对 | 在「我是谁 / 对方是谁」里分别填昵称 |
| 记录太长很慢很贵 | 调小「每段消息条数」「最多分段数」，或只截取最近 1-2 周的记录 |
| 想换端口 | `node tools\launch.js --port 6000` |
| 页面打开是白屏 | 必须通过 `start.bat` / `node server.js` 打开，不能直接双击 `public/index.html`（那样没有后端） |

## 六、隐私与免责

- 服务只监听 `127.0.0.1`，同一局域网内其它设备也访问不到；关掉窗口即停止。
- 只有你点「开始分析」或「预演一下」时，聊天内容才会发给你自己配置的模型接口；勾「只看本地统计」则完全不出本机。
- `config.json` 里可能有你的 Key，别提交到公开仓库（建议自行加进 `.gitignore`）。
- 模型的判断是**概率性推测**，不是读心术。它擅长的是帮你把话说得更清楚，而不是替你决定这段关系怎么走。涉及分手、表白这类大事，请把它当一个旁观朋友的视角，而不是结论。
